### ⏱️ ช่วงที่ 2: Zero-Error Setup (รันสดตาม README ไร้ Error) (0:35 – 2:05)

**🎬 แอ็กชันหน้าจอ:**
1. เปิด Terminal 2 หน้าต่างคู่กัน (ซ้าย: Backend, ขวา: Frontend)
2. **Terminal ฝั่งซ้าย (Backend):**
   ```bash
   cd backend
   uv sync
   uv run python manage.py migrate
   uv run python manage.py bootstrap_oidc
   uv run python manage.py bootstrap_dormmate
   uv run python manage.py runserver 8000
   ```
   *(ชี้เมาส์ให้เห็นข้อความว่า Server ทำงานอยู่ที่ `http://127.0.0.1:8000/`)*
3. **Terminal ฝั่งขวา (Flutter Frontend):**
   ```bash
   flutter pub get
   flutter run -d chrome --web-port 50000
   ```
   *(รอประมาณ 10-20 วินาทีจนเบราว์เซอร์ Chrome เด้งเปิดหน้าเว็บ `http://localhost:50000` ขึ้นมา)*

**🎙️ บทพูด:**
> "ในส่วนที่สอง เราจะมาสาธิตขั้นตอน **Zero-Error Setup** โดยรันคำสั่งตาม README ทีละบรรทัดให้เห็นแบบสด ๆ ครับ  
> 
> เริ่มต้นที่ **Terminal ฝั่งซ้าย สำหรับ Backend**:  
> 1. เราเข้าโฟลเดอร์ `cd backend`  
> 2. สั่ง `uv sync` เพื่อติดตั้ง Dependencies  
> 3. สั่ง `uv run python manage.py migrate` สร้างตารางฐานข้อมูล  
> 4. สั่ง `uv run python manage.py bootstrap_oidc` เพื่อตั้งค่า OIDC Client และสร้างกุญแจ RSA Signing Key  
> 5. สั่ง `uv run python manage.py bootstrap_dormmate` เพื่อโหลดข้อมูล Mockup ทั้งห้องพัก บิล และประกาศ  
> 6. และสั่ง `uv run python manage.py runserver 8000` เพื่อเปิด API Server และ OIDC Provider บนพอร์ต 8000 ครับ  
> 
> ต่อไปที่ **Terminal ฝั่งขวา สำหรับ Flutter Frontend**:  
> 1. สั่ง `flutter pub get`  
> 2. จากนั้นสั่ง `flutter run -d chrome --web-port 50000` โดยกำหนด Web Port เป็น 50000 ให้ตรงกับ Redirect URI ที่ลงทะเบียนไว้กับระบบ OIDC ครับ  
> 
> จะเห็นได้ว่า Chrome เปิดขึ้นมาและพร้อมใช้งานทันทีโดยไม่มี Error ใด ๆ เลยครับ"

### ⏱️ ช่วงที่ 3: OIDC Authentication, Route Guard & Session Persistence (2:05 – 3:15)

**🎬 แอ็กชันหน้าจอ:**
1. **โชว์ Route Guard:** 
   - ลองพิมพ์ใน Address Bar: `http://localhost:50000/#/home` หรือ `#/expenses` แล้วกด Enter
   - ชี้ให้เห็นว่าระบบ Route Guard จะดีดกลับมาที่หน้า `#/login` เสมอหากยังไม่ล็อกอิน
2. **การล็อกอิน SSO:**
   - กดปุ่ม **"Sign in with SSO"**
   - เบราว์เซอร์จะ Redirect ไปยังหน้า Login ของ Django OIDC Provider (`127.0.0.1:8000/login/`)
   - กรอก Username: `test` และ Password: `1234` (หรือ `demouser` / `demo12345`)
   - กดปุ่ม **"Sign in"**
   - ระบบจะ Authorization และ Redirect กลับมาที่ `localhost:50000/callback` และเข้าสู่หน้าหลัก Dashboard ทันทีอย่างราบรื่น (ไม่มีหน้า Consent ค้าง)
   - หน้าจอ Dashboard แสดงข้อมูลชื่อ "Test User" และห้อง "Room B-204"
3. **โชว์ Session Persistence:**
   - กดปุ่ม **F5 เพื่อรีเฟรชหน้าเว็บ** 
   - แสดงให้เห็นว่าแอปยังคงอยู่ที่หน้า Dashboard ไม่หลุดกลับไปหน้า Login เพราะ Token ถูกเก็บไว้อย่างปลอดภัยใน Storage
4. **โชว์ Logout:**
   - กดไปที่เมนู **"โปรไฟล์" (Profile)** ด้านล่าง
   - เลื่อนลงมากดปุ่ม **"ออกจากระบบ" (Sign Out)** -> กดยืนยัน
   - ระบบจะล้าง Token และดีดกลับมาที่หน้า Login อย่างสมบูรณ์

**🎙️ บทพูด:**
> "ช่วงที่ 3 เป็นระบบความปลอดภัย **OIDC Authentication** ครับ  
> 
> เริ่มต้นด้วย **Route Guard**: หากผู้ใช้ยังไม่ได้ล็อกอิน แล้วพยายามเข้าถึง URL ภายใน เช่น `/home` หรือ `/expenses` ระบบจะบล็อกและ Redirect กลับมาที่หน้า Login เสมอครับ  
> 
> ตอนนี้เราจะกดปุ่ม **'Sign in with SSO'** เพื่อเข้าสู่ระบบผ่านมาตรฐาน OpenID Connect ครับ เบราว์เซอร์จะเชื่อมต่อไปยังหน้า Authentication ของ Django เราจะใช้ Demo Account คือ `test` และรหัสผ่าน `1234`  
> 
> เมื่อกด Sign in ระบบจะทำการแลกเปลี่ยน Authorization Code กับ Token และพาเราเข้าสู่หน้าหลัก Dashboard ของหอพักทันทีครับ จะเห็นข้อมูลชื่อผู้พัก Test User และหมายเลขห้อง B-204  
> 
> และเมื่อเราทดสอบ **Session Persistence** ด้วยการกด Refresh หน้าเว็บ F5... จะเห็นว่าระบบยังคงจดจำสถานะล็อกอินอยู่ได้อย่างสมบูรณ์ครับ  
> 
> สุดท้าย เมื่อไปที่หน้า Profile แล้วกด **'ออกจากระบบ'** แอปจะล้าง Access Token ทิ้งทันทีและกลับสู่หน้า Login อย่างปลอดภัยครับ"

### ⏱️ ช่วงที่ 4: Core Functions (CRUD) & Error Handling (3:15 – 4:45)

**🎬 แอ็กชันหน้าจอ:**
1. กดปุ่ม Login กลับเข้ามาที่ Dashboard อีกครั้ง
2. **Read (อ่านข้อมูล):**
   - แตะที่แท็บ **"แจ้งซ่อม" (Maintenance)**
   - แสดงรายการคำขอแจ้งซ่อม (List View) พร้อมฟิลเตอร์แท็บ (ทั้งหมด, รอดำเนินการ, กำลังซ่อม, เสร็จสิ้น)
   - แตะการ์ดแจ้งซ่อมอันใดอันหนึ่งเพื่อเข้าสู่ **Detail View** แสดง Timeline ความคืบหน้า วันที่ และระดับความเร่งด่วน
   - กดปุ่มย้อนกลับมาที่หน้ารายการ
3. **Create (สร้างข้อมูลใหม่ + Form Validation):**
   - กดปุ่ม **`+` (Floating Action Button)** ด้านล่างเพื่อเปิดหน้าต่าง "แจ้งซ่อมใหม่"
   - **โชว์ Error Handling ครั้งที่ 1:** ไม่กรอกข้อมูล แล้วกดปุ่ม "ยืนยันการแจ้งซ่อม" ทันที -> แสดงข้อความ Validation Error สีแดงแจ้งเตือน
   - กรอกข้อมูลจริง:
     - หัวข้อ: *ก็อกน้ำอ่างล้างหน้ารั่ว*
     - หมวดหมู่: *ระบบประปา*
     - ความเร่งด่วน: *สูง*
     - รายละเอียด: *มีน้ำหยดตลอดเวลาใต้ข้อต่ออ่างล้างหน้า*
   - กดปุ่ม **"ยืนยันการแจ้งซ่อม"** -> แสดง SnackBar สำเร็จ และตั๋วใหม่ปรากฏขึ้นในรายการทันที
4. **Update / Delete (ยกเลิกตั๋วแจ้งซ่อม):**
   - แตะเข้าไปในตั๋วแจ้งซ่อมที่เพิ่งสร้าง
   - กดปุ่ม **"ยกเลิกคำขอ" (Cancel Request)** ด้านล่าง -> กดยืนยันใน Dialog
   - แสดง SnackBar แจ้งว่ายกเลิกสำเร็จ และสถานะเปลี่ยนเป็น Cancelled ทันที
5. **โชว์ Error Handling ครั้งที่ 2 (Network / Server Failure):**
   - สลับไปที่ Terminal Backend กด **`Ctrl + C`** เพื่อหยุดเซิร์ฟเวอร์ชั่วคราว
   - สลับกลับมาที่แอปพลิเคชัน แล้วลองเปลี่ยนแท็บ หรือกดรีเฟรชหน้ารายการ
   - **ชี้ให้อาจารย์เห็นว่าแอปไม่แครช (No Crash)** โดยแสดงหน้าจอแจ้งเตือนข้อผิดพลาดอย่างสุภาพ พร้อมปุ่ม **"ลองใหม่อีกครั้ง" (Retry)**
   - สลับไป Terminal Backend รัน `uv run python manage.py runserver 8000` อีกครั้ง
   - สลับกลับมาที่แอป กดปุ่ม **"ลองใหม่อีกครั้ง"** ข้อมูลกลับมาโหลดและแสดงผลได้ตามปกติ

**🎙️ บทพูด:**
> "ส่วนที่ 4 เราจะมาสาธิตฟังก์ชันหลักตามแนวคิด **CRUD** และการรับมือข้อผิดพลาด **Error Handling** ครับ
