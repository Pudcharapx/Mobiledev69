### 🖥️ สิ่งที่ต้องแสดงบนหน้าจอ:
1. **ทดสอบ Route Guard:** ลองเปลี่ยน URL ในเบราว์เซอร์ไปที่ `http://localhost:50000/#/` หรือ `#/expenses` จะเห็นว่าระบบดีดกลับมาที่หน้า `#/login` เสมอ
2. **การเข้าสู่ระบบ:**
   - แสดงให้เห็น Demo Account ในฟอร์ม: `test` / `1234` (หรือคลิกปุ่ม OIDC Login)
   - ชี้ให้เห็น URL Bar ว่ามีการเชื่อมต่อไปยัง Django OIDC Provider
   - เมื่อล็อกอินสำเร็จ หน้าจอเปลี่ยนไปยังหน้าหลัก Dashboard แสดงชื่อผู้ใช้ "Test User" และห้อง "Room B-204"
3. **ทดสอบ Session Persistence:** กดปุ่ม **Refresh หน้าเว็บ (F5)** หรือปิด Tab แล้วเปิด `http://localhost:50000` ขึ้นมาใหม่ แอปยังคงเข้าหน้า Dashboard ทันที ไม่หลุดกลับไปหน้า Login เพราะมี `flutter_secure_storage` บันทึก Token เอาไว้
4. **ทดสอบ Logout:** ไปที่แท็บ Profile ด้านล่าง เลื่อนลงมากดปุ่ม **"ออกจากระบบ" (Sign Out)** -> ยืนยัน -> หน้าจอเด้งกลับสู่หน้า Login พร้อมล้าง Token ในเครื่องเรียบร้อย

### 🎙️ บทพูด (Voiceover):
> *"ช่วงที่ 3 คือหัวใจสำคัญของระบบความปลอดภัย นั่นคือ **OpenID Connect (OIDC) Authentication** ครับ*  
> 
> *ประการแรก เรามี **Route Guard** ที่ควบคุมด้วย GoRouter โดยเมื่อผู้ใช้ยังไม่ได้ยืนยันตัวตน หากพยายามเข้าสู่ URL ปลายทาง เช่น `/expenses` หรือ `/maintenance` ระบบจะบล็อกและ Redirect กลับมาที่หน้า Login โดยอัตโนมัติครับ*  
> 
> *ตอนนี้เราจะทำการล็อกอินด้วยบัญชีทดสอบที่ระบุไว้ใน README คือ Username: `test` และ Password: `1234` ครับ เมื่อกดเข้าสู่ระบบ แอปพลิเคชันจะทำการตรวจสอบสิทธิ์และรับ Bearer Access Token มาเก็บไว้อย่างปลอดภัยใน `flutter_secure_storage`*  
> 
> *เมื่อเข้ามาแล้ว ที่หน้า Home Dashboard จะดึงข้อมูลเฉพาะบุคคลของผู้ใช้รายนี้ขึ้นมา เช่น ชื่อผู้พัก Test User และหมายเลขห้อง B-204 ครับ*  
> 
> *เราจะทดสอบ **Session Persistence** ด้วยการกด Refresh หน้าเว็บ F5 ครับ... จะเห็นว่าแอปยังคงจดจำ Session และคงสถานะล็อกอินอยู่ได้อย่างสมบูรณ์*  
> 
> *และเมื่อต้องการออกจากระบบ เราไปที่หน้า Profile แล้วกดปุ่ม 'ออกจากระบบ' ระบบจะล้าง Access Token ในเครื่องทิ้งทันที และดีดกลับสู่หน้า Login อย่างถูกต้องครับ"*

### 🖥️ สิ่งที่ต้องแสดงบนหน้าจอ:
1. **ล็อกอินกลับเข้ามาใหม่อีกครั้ง** เพื่อเข้าสู่หน้าจอ Dashboard
2. **Read (อ่านข้อมูล):**
   - ไปที่แท็บ **"แจ้งซ่อม" (Maintenance)** แสดงรายการคำร้องขอซ่อมที่มีอยู่เดิม (List View) พร้อมฟิลเตอร์สถานะ (ทั้งหมด, รอดำเนินการ, กำลังซ่อม, เสร็จสิ้น)
   - แตะที่การ์ดแจ้งซ่อมเพื่อเข้าไปดู **Detail View** (แสดง Timeline ความคืบหน้า, วันที่แจ้ง, หมวดหมู่ และระดับความเร่งด่วน)
3. **Create (สร้างข้อมูลใหม่ + Form Validation):**
   - กดปุ่ม **`+` (Floating Action Button)** เพื่อเปิดหน้าจอ "แจ้งซ่อมใหม่"
   - **โชว์ Error Handling ครั้งที่ 1:** ปล่อยช่องว่างไว้แล้วกดส่งคำขอ -> แสดงการแจ้งเตือน Validation Error สีแดงชัดเจน
   - กรอกข้อมูลจริง:
     - หัวข้อ: *ก็อกน้ำอ่างล้างหน้ารั่ว*
     - หมวดหมู่: *ระบบประปา (Plumbing)*
     - ความเร่งด่วน: *สูง (High)*
     - รายละเอียด: *น้ำหยดตลอดเวลาใต้ข้อต่ออ่างล้างหน้า*
   - กดปุ่ม "ยืนยันการแจ้งซ่อม" -> แสดง SnackBar สำเร็จ และหน้ารายการมีตั๋วใหม่ปรากฏขึ้นทันที
4. **Delete / Update (ยกเลิกและอัปเดตสถานะ):**
   - แตะเข้าไปในตั๋วแจ้งซ่อมอันที่เพิ่งสร้าง
   - กดปุ่ม **"ยกเลิกคำขอ" (Cancel Request)** ด้านล่าง -> ยืนยัน Dialog
   - แสดง SnackBar แจ้งว่ายกเลิกสำเร็จ และสถานะของตั๋วถูกปรับเป็น Cancelled ทันที
5. **โชว์ Error Handling ครั้งที่ 2 (Network / Server Failure):**
   - สลับไปที่ Terminal Backend กด `Ctrl + C` เพื่อหยุดเซิร์ฟเวอร์ชั่วคราว
   - สลับกลับมาที่แอปแล้วกดดึงหน้าจอเพื่อรีเฟรช (Pull to Refresh) หรือเปลี่ยนแท็บ
   - ชี้ให้อาจารย์เห็นว่า **แอปไม่แครช (No Crash)** แต่จะแสดง Error State หน้าจออย่างเป็นมิตร พร้อมปุ่ม "ลองใหม่อีกครั้ง (Retry)" และแจ้งเตือน SnackBar ข้อความ Network Connection Error
   - สลับไป Terminal Backend แล้วรันใหม่อีกครั้ง กด Retry ในแอป ข้อมูลกลับมาแสดงตามปกติ
